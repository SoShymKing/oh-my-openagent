# OMO Senpi adapter

## Browser user input

Tau submits explicit browser prompts and skill commands through the optional
`omo:send-user-input` extension event:

```ts
const request = {
  sessionId: ctx.sessionManager.getSessionId(),
  send: () => pi.sendUserMessage(content, options),
  handled: false,
}
pi.events.emit("omo:send-user-input", request)
if (!request.handled) request.send()
```

`sessionId` is the durable host session ID, not Tau's gateway ID. The matching
adapter invokes `send` synchronously inside an asynchronous submission context.
No listener, a foreign session, or an inactive adapter leaves the request
unclaimed so Tau falls back to the normal send.

The composition root installs input attribution before registering components.
Every OMO input hook sees the initiating browser input as `rpc` while the actual
host event remains extension-sourced. This covers keyword injection, plan request
tracking, continuation resets and queued reminders, memory accepted-turn
accounting, fallback reminders, and prompt telemetry without replaying handlers.
The host retains ownership of input IDs, asynchronous transform chaining,
images, queue modes, skill expansion, and disposition events.

Explicit skill syntax includes leading `/skill:name`, `$name`, and `$skill:name`
tokens, chained leading invocations, and inline `$skill:name`. The tracker observes
those names before native expansion, and keyword hooks avoid duplicate skill
content. Ordinary inline dollar variables remain literal. Native extension
commands run before the input pipeline; prompts generated by their handlers
remain programmatic rather than acquiring browser-user provenance.

Each submission can attribute only its first host input ID. Other extension
sends, including later sends inheriting its async context, remain suppressed.
Session shutdown invalidates outstanding submissions and removes the listener.
The event bus is a trusted extension coordination surface, not a security
boundary against arbitrary code executing in the extension process.

Load both the matching Tau extension and the rebuilt OMO adapter, then restart
OMO to activate the change. No Senpi engine modification is required.
